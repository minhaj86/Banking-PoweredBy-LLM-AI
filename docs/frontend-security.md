# Placeholder Bank - Frontend and document security

- Browser authentication is an opaque HttpOnly session cookie. Access/refresh/ID tokens are encrypted server-side, never exposed through API bodies, web configuration, JavaScript storage, document URLs or application logs.
- All cookie mutations, including multipart upload and logout, require a session CSRF token. The browser API client centralizes credentials, CSRF renewal, correlation IDs, cancellation, stable mutation intent keys and `If-Match` versions.
- Unauthenticated API requests return a JSON 401. Statuses 403, 404, 409, 422, 429 and temporary 5xx have distinct recovery copy. A failed submission/decision is not automatically retried after login.
- Query keys include tenant and stable identity. Identity, permission or session changes clear sensitive caches. Protected route remounts discard local form state. There is no analytics/session replay, sensitive console logging, service worker or offline persistence.
- The BFF destination, methods, UUID paths and query parameter names are allowlisted. Downstream redirects and cookies are not forwarded. Upload limits apply at gateway, BFF and loan-service. Documents stream through the BFF; the existing backend enforces its own bounded storage handling.
- Documents are authorized on every nested lookup and audited on content access. Quarantined evidence cannot be previewed. PDF.js is pinned and loaded lazily with a separate worker, XFA disabled, a restrictive script policy and canvas rendering. PNG/JPEG previews use server-validated media types. Uploaded HTML/SVG and raw AI-generated HTML are never rendered.
- Sensitive responses use `Cache-Control: no-store`. Only hashed static assets are publicly cacheable. CSP restricts scripts/connections/workers to the origin, prevents objects and embedding, and permits inline styles for Material UI's generated styles. Referrer policy is `no-referrer`; MIME sniffing is disabled. There is no permissive cross-origin credential CORS.
- The gateway clears untrusted forwarded headers and the BFF ignores forwarded-header interpretation. Canonical callback/logout origins come from trusted configuration; return paths are restricted to portal path segments and cannot supply an origin, query string or traversal.
- Database/storage/provider/IAM administration credentials are absent from browser configuration and the BFF environment. Frontend build arguments contain no secrets. The test-only Node/Docker fixtures hold synthetic credentials outside the browser and their local reports/authenticator state are ignored by version control.

Production needs HTTPS throughout exposed authentication paths, Secure cookies, appropriate trusted proxy/network configuration, private Redis with TLS/access controls, managed secret/encryption key rotation, dependency maintenance and a retention/legal-hold process. The local mail catcher and Keycloak development mode are not production deployment choices.

The optional Vite overlay has a separate development-only CSP for the inline React refresh preamble and gateway WebSocket. Normal static deployment retains `script-src 'self'` without inline-script permission. See [development setup](deployment-and-scaling.md#same-origin-vite-development).

Automated axe checks cover the public dashboard and main application/review/loan flows, with desktop/mobile screenshots for visual inspection. Keyboard focus, form labels, dialog confirmation and text status labels are implemented; automated checks do not certify accessibility for every assistive technology.
